Data redundancy & deduplication pipeline.

A Python and AWS workflow built during my cloud internship at CodeAlpha. Incoming records are validated and checked against existing DynamoDB data before persistence.

Unique records
RESULT

Problem

Duplicate records can reduce data quality and create unnecessary storage or processing overhead.

Approach

Validate incoming data, compare it with existing records, filter duplicates and persist only unique entries.

Result

A 10-row validation dataset produced 6 retained records after 4 redundant rows were filtered.

Why DynamoDB?
The project required straightforward key-based record lookup against existing cloud data.
Why Boto3?
It allowed the Python workflow to interact directly with DynamoDB and keep the data-processing logic in one script.
Validate before write
Filtering before persistence avoids having to clean up duplicates after they have already entered storage.
Least privilege
The AWS identity should receive only the permissions required by the pipeline rather than broad access.
10 input records
