FEATURED PROJECT

AWS DynamoDB Data Redundancy & Deduplication Pipeline

A cloud data preprocessing workflow designed to prevent duplicate records from reaching DynamoDB. Built during my CodeAlpha cloud internship.

Inspect the repository ↗
Problem

Duplicate records can reduce data quality and introduce unnecessary storage and processing overhead.

Approach

Incoming CSV records are validated, compared against existing DynamoDB data and filtered before persistence.

Architecture
CSV input ↓ Python validation ↓ Boto3 ↓ IAM ↓ DynamoDB ↓ Unique records
Engineering decisions

DynamoDB provides the lookup layer, Boto3 keeps AWS interaction inside the Python workflow, and validation occurs before persistence rather than cleaning the database afterward. IAM access is scoped around the pipeline's required operations.

10 validation records
4 duplicates filtered
6 unique records retained

Working method

Debug before
you guess.

Infrastructure problems rarely announce the exact thing that failed. I'm developing the habit of narrowing a problem down systematically instead of changing random things until something works.

Whether the problem is a service that isn't responding, a device losing its connection or a permission failure, the approach stays similar: establish what actually happened, isolate the failing layer, verify the fix and record what was learned.

02 Isolate
03 Inspect
04 Identify
